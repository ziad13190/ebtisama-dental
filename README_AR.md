# منصة عيادة ابتسامة — تطوير الواجهة ولوحة الإدارة

هذه نسخة تطوير من المشروع القائم. لا تنشئ مشروعًا جديدًا؛ فك الضغط وافتح مجلد `ebtisama-dental` نفسه في VS Code.

## المتطلبات
- Node.js 20.9 أو أحدث (يفضل Node.js LTS).
- VS Code.
- اتصال إنترنت أول مرة لتثبيت الحزم.

## التشغيل على Windows
1. فك ضغط الملف، وافتح المجلد الداخلي `ebtisama-dental` الذي يحتوي على `package.json`.
2. افتح Terminal داخل هذا المجلد.
3. نفّذ:
   ```bash
   npm install
   ```
4. لو هذه أول مرة تشغّل المشروع، انسخ `.env.example` وسمِّ النسخة `.env`. **لو عندك ملف `.env` قديم من الموقع السابق، احتفظ به ولا تستبدله**؛ انقل فقط أي إعدادات ناقصة من المثال بعد مراجعتها. لا ترفع `.env` إلى Git ولا ترسله لأي شخص.
5. غيّر `ADMIN_PASSWORD` إلى كلمة مرور قوية، وغيّر `ADMIN_SESSION_SECRET` إلى قيمة عشوائية طويلة لا تقل عن 32 حرفًا.
6. لو عندك قاعدة بيانات قديمة من تشغيل سابق، احتفظ بنسخة احتياطية منها قبل التحديث. مع الإعداد الافتراضي `DATABASE_URL="file:./dev.db"` يكون الملف عادةً داخل مجلد `prisma`؛ انسخه باسم آخر قبل تنفيذ الأمر. لا تحذف قاعدة البيانات القديمة.
7. أنشئ/حدّث قاعدة البيانات:
   ```bash
   npx prisma db push
   ```
8. شغّل الموقع:
   ```bash
   npm run dev
   ```
9. افتح `http://localhost:3000`، ولوحة الإدارة `http://localhost:3000/admin`.

## الموجود في لوحة الإدارة
- نظرة عامة وإحصائيات تشغيلية وإشعارات محفوظة.
- متابعة طلبات الحجز ومراجعة الدفع يدويًا.
- تسجيل حجز من الاستقبال، وإلغاء الموعد أو تعديل موعده.
- ملفات مرضى مختصرة مجمعة برقم الهاتف وسجل طلباتهم.
- إضافة الأطباء وتعديل بياناتهم وساعات وأيام عملهم والاستراحة ومدة الموعد. أرشفة الطبيب تخفيه من نموذج الحجز ولا تمسح حجوزاته السابقة.
- تقويم إداري لإغلاق وقت محدد لطبيب أو لكل الأطباء، مثل الإجازات وأعمال الصيانة.
- إنشاء إعلان إضافي وتحديد وقت بدايته وانتهائه وتفعيله؛ لا يظهر الإعلان خارج فترة الصلاحية.
- إعداد رسوم الحجز وساعات العيادة الافتراضية وألوان الهوية.
- تقارير تشغيلية وإيرادات محسوبة فقط من الدفع الذي اعتمدته الإدارة.

## المواعيد ومنع التداخل
نموذج الحجز يقرأ الأطباء النشطين من قاعدة البيانات ويطلب المواعيد المتاحة حسب جدول الطبيب والاستراحة والإجازات والحجوزات المسجلة. يتم فحص الموعد مرة أخرى على السيرفر قبل الحفظ، كما يوجد قيد فريد على الطبيب والموعد نفسه لتقليل تعارض الطلبات المتزامنة.
طلبات الدفع المعلقة تحجز الموعد مؤقتًا لحين المراجعة أو الرفض/الإلغاء؛ لا يوجد انتهاء تلقائي للحجز المعلق في النسخة الحالية.

## الدفع — وضع تجهيزي فقط
تظهر خيارات المحفظة وInstaPay وفوري كواجهات وتعليمات، لكن **لا يوجد اتصال فعلي أو تحصيل تلقائي** مع أي مزود دفع. الرقم `01042099891` قابل للتعديل من إعدادات العيادة. قد يرسل العميل مرجع تحويل اختياريًا، ولا يعتبر ذلك إثباتًا للدفع. الإدارة وحدها تراجع وصول الأموال من التطبيق/حساب التاجر وتضغط «تأكيد استلام الدفع والحجز».
لا تدخل مفاتيح API وهمية ولا تعتبر رسالة العميل أو صورة الإيصال إثباتًا تلقائيًا. عند التعاقد لاحقًا يجب تنفيذ التكامل على السيرفر والتحقق من توقيع Webhook وفق وثائق المزود الرسمية.

## الإشعارات والبريد
- إشعارات الإدارة والعميل تُحفظ في قاعدة البيانات. يستطيع العميل متابعة الطلب من أسفل الصفحة باستخدام كود الطلب ورقم الهاتف.
- رسائل البريد لا تعمل إلا بعد ضبط SMTP الحقيقي في `.env`. إذا لم تضبط SMTP، سيظل الطلب محفوظًا في لوحة الإدارة.
- لا توجد إشعارات Push أو رسائل WhatsApp آلية في هذه النسخة؛ زر WhatsApp يفتح المحادثة فقط.

## الأمان وحدود الجاهزية
هذه نسخة تطوير محلية وليست اعتمادًا أمنيًا أو تصريحًا بالنشر التجاري. قبل استقبال بيانات مرضى حقيقية أو إطلاق الموقع:
- انشر عبر HTTPS، واستخدم PostgreSQL بدل SQLite للبيئة الإنتاجية، واضبط نسخًا احتياطيًا واختبر الاستعادة.
- أضف سياسة خصوصية وموافقة واضحة، وراجع صلاحيات الوصول والاحتفاظ بالبيانات.
- استخدم أسرارًا قوية، ومزود بريد موثوقًا، وحدد الأدوار (مالك/استقبال/طبيب) عند تعدد الموظفين.
- راجع قيود المواعيد والتعامل مع التزامن واختبرها تحت ضغط فعلي.
- أجرِ مراجعة أمنية واختبارات قبل استخدام النظام سريريًا أو تجاريًا.

## ملاحظات
- مجسم الضرس في الواجهة مرسوم بشكل إجرائي ثلاثي الأبعاد باستخدام Three.js، مع بديل CSS في حال عدم دعم WebGL وتقليل الحركة حسب إعداد الجهاز؛ وهو ليس نموذج GLB طبيًا معتمدًا.
- المساعد داخل الصفحة مساعد استقبال إرشادي بقواعد ثابتة، وليس نموذج ذكاء اصطناعي ولا يشخّص الحالات.
- البيانات الحالية محلية في SQLite. لا ترسل ملف قاعدة البيانات أو بيانات المرضى إلى أي جهة.
- لا تضع ملف `.env` أو نسخة قاعدة البيانات داخل ملف ZIP عند مشاركة المشروع.

## إضافات تجربة المريض في هذه النسخة
- الإعلانات النشطة تظهر في نافذة وسط الشاشة بزر «موافق» بدل الشريط العلوي.
- شاشة ترحيب أول زيارة، ومفتاح مظهر داكن/فاتح، ومفتاح تجريبي لاتجاه اللغة. ترجمة جميع النصوص إلى الإنجليزية ما زالت تحتاج مرحلة ترجمة كاملة ومراجعة تحريرية؛ المفتاح الحالي لا يُعد ترجمة مكتملة.
- حاسبة نطاقات سعرية استرشادية قابلة للتعديل داخل الواجهة، وليست تسعيرًا نهائيًا.
- مكوّن مقارنة قبل/بعد بصورتين يحمّلهما المستخدم، ويُفضّل استخدام صور بموافقة أصحابها فقط.
- تسجيل صوتي محلي في المتصفح. التسجيل لا يُرفع تلقائيًا ولا يُحفظ في قاعدة البيانات؛ يستطيع المريض تشغيله ثم إرساله يدويًا للعيادة.
- نموذج بيانات طبية مشفر باستخدام AES-256-GCM. لا يعمل قبل إعداد `MEDICAL_DATA_ENCRYPTION_KEY` (64 خانة hex عشوائية) على السيرفر. لا تحفظ المفتاح في Git أو الواجهة. واجهة عرض السجل للطبيب داخل لوحة الإدارة ما زالت تحتاج شاشة وصلاحيات منفصلة قبل الاستخدام السريري.
- عند إنهاء الزيارة من لوحة الإدارة، تُحفظ رسالة إرشادات عامة في إشعارات المريض. يجب على الطبيب إضافة تعليمات خاصة بالحالة خارج هذه الرسالة العامة.
- إرسال واتساب آلي اختياري عبر WhatsApp Cloud API بعد موافقة المريض. يحتاج حساب Meta Business مؤهلًا وإعداد القالب/سياسة الرسائل؛ عند غياب المفاتيح يبقى غير مفعّل. رسائل الحالات من لوحة الإدارة تستخدم نفس الربط.
- أداة «محاكي الابتسامة» هنا معاينة صورة فقط، وليست ذكاء اصطناعيًا ولا تغيّر شكل الأسنان. يلزم مزود معالجة صور/AI متخصص، موافقة صريحة، وضوابط خصوصية قبل إضافة محاكاة فعلية.

## إعدادات التكامل الإضافية
أنشئ مفتاح تشفير طبي عشوائيًا على جهاز موثوق (مثال باستخدام Node):
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
ضع الناتج في `MEDICAL_DATA_ENCRYPTION_KEY` داخل `.env` على السيرفر فقط. لا تفقد المفتاح؛ بدونه لا يمكن فك السجلات الطبية القديمة. لإرسال واتساب، أضف `WHATSAPP_CLOUD_API_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID` بعد إعداد حساب Meta الرسمي.

## حدود مهمة قبل الاستخدام التجاري/الطبي
هذه نسخة تطوير وليست اعتمادًا طبيًا أو قانونيًا أو أمنيًا نهائيًا. اختبر كل مسار في بيئة تجريبية، واطلب مراجعة أمنية/خصوصية. لا تستخدم السجل الطبي أو محاكي الابتسامة لاتخاذ قرار علاجي آلي. لا ترسل بيانات طبية عبر واتساب. أداة اللغة الحالية لم تترجم الموقع بالكامل بعد، ومساعد الأسئلة الشائعة الحالي ردود ثابتة وليس نموذج ذكاء اصطناعي متصلًا.
